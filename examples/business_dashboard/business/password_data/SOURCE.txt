This public wordlist is not application credentials or recovery material.
The application loads it locally and never sends a prospective password or its
hash to an external service. It compares whole passwords case-insensitively,
ignoring surrounding whitespace for screening only; hashing and sign-in retain
the exact supplied characters. It also rejects exact account/service names.

Predictable-repeat screening is a local extension, not part of the upstream
corpus: a candidate is rejected when its entire normalized value consists of
two or more identical repetitions of an entry in the bundled corpus. The
implementation checks only lengths dividing the candidate's length, from one
through the shorter of half the candidate length and the longest corpus entry
(33 characters in this snapshot). Each unit is checked by exact set membership;
the repeated unit must reconstruct the entire candidate. This adds at most 33
set lookups per attempt and never rejects an unrelated phrase merely because
it contains a common word. It imposes no character-class composition rules.

This is a pinned snapshot, not a comprehensive or current breached-password
database, and passing screening does not establish password strength or
uniqueness. Maintainers must review upstream data updates explicitly, replace
the corpus and license together when appropriate, update this provenance and
its checksum regression, and rerun password and source-distribution checks.
